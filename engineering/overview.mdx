## Why these practices exist

AI changed the economics of our development loop. Three things got dramatically cheaper: building, interrogating a plan, and decomposing a finished branch into reviewable PRs. Two things did not: the judgment half of code review, and product validation. Our processes move human attention to where it is still the constraint.

The operating principles:

1. **Design still goes first.** Cheap building does not mean skipping thinking. It means the thinking happens in an interrogated plan and (when novel) a committed spec, not in review comments after the fact.
2. **Validate the product before reviewing the code.** A demo catches "built the wrong thing" while it is cheap to fix. Code review should never be the first time someone sees a feature.
3. **PR boundaries are discovered, not pre-planned.** We build end-to-end first, then split along the seams the code revealed. Splitting is a prompt now.
4. **Prototype code is disposable; prototype intent is not.** PM and designer prototypes are living specs. The validated flows transfer; the code gets rebuilt in our stack.
5. **Decisions get written down.** ADRs and specs are how a small team stays legible to itself, and how our coding agents inherit context instead of re-deciding architecture per session.
6. **AI output is untrusted input.** We hold AI-generated code to a higher verification bar, not a lower one. The data is unambiguous: AI-generated code carries measurably more defects and security flaws than human-written code.

## This is the new lifecycle

The old feature lifecycle (PRD → design → ESD → Linear → dogfooding → QA → release) no longer reflects how we work. Work doesn't start from PRDs anymore; it starts from design prototypes. And there is no QA team; verification is built into the workflow itself through the demo gate, the testing bar, and dogfooding.

These practices are the replacement, end to end:

- **Intake** happens through the [prototype-to-production pipeline](/engineering/prototype-to-production) when work originates as a PM/designer prototype, or directly through the [development workflow](/engineering/development-workflow) when it originates in engineering.
- **Verification** is the demo gate, the [testing bar for AI-generated code](/engineering/working-practices#the-testing-bar-for-ai-generated-code), and dogfooding before release.
- **Decisions** are captured in [ADRs](/engineering/adr-practice) and specs as we go, in the same PRs as the code.
